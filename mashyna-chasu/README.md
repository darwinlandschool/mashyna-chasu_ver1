# «Машина часу»

Невелика браузерна візуальна новела від DarwinLand: гравець проживає шкільний тиждень у 2000 або 2026 році, робить 15 сюжетних виборів, переживає випадкові й кризові події та наприкінці відкриває свій профіль рішень.

## Запуск

Потрібен Node.js 20 або новіший.

```bash
npm install
npm run dev
```

Vite покаже локальну адресу, зазвичай `http://localhost:5173`.

Production-збірка й локальний перегляд:

```bash
npm run build
npm run preview
```

Автоматичні тести:

```bash
npm test
```

## Де що редагувати

- `src/data/storyCards.ts` — усі 15 карток, тексти двох епох, варіанти, реакції, базові ефекти й сюжетні прапорці.
- `src/data/randomEvents.ts` — випадкові події та правила вибору без повторів.
- `src/data/crises.ts` — кризові картки для Знань, Своїх, Енергії та Монет.
- `src/game/deferredEffects.ts` — відкладені наслідки між ходами.
- `src/data/finalProfiles.ts` і `src/game/finalProfile.ts` — тексти та алгоритм фінальних профілів.
- `src/data/profileLinks.ts` — посилання на навчальні курси. Поки URL порожній, кнопка курсу не показується.
- `src/styles/` — дизайн-токени з офіційною палітрою DarwinLand 2026, теми епох, адаптивність і анімації.
- `public/assets/characters/` — портрети героїв: оптимізовані `.jpg` завантажуються першими, а оригінальні `.png` використовуються як автоматичний fallback. Під час заміни портрета оновіть обидва файли з однаковою назвою.
- `public/assets/brand/` — офіційні SVG-логотипи та брендова зірка з `DarwinLand-Presentation-System`.
- `public/assets/fonts/` — фірмові Jiho Soft Bold і Mulish з бренд-системи.

## Бренд-система

Інтерфейс використовує кольори з `Brandbook DarwinLand_2026.pdf`: базові `#FBFBFB` і `#1F1F1F`, а також кольори ідентичності `#44B5E8`, `#B6EF17`, `#FB8ECB`, `#FAEC1F`. Заголовки набрані Jiho Soft Bold, основний текст — Mulish. Компонент логотипу підключає готовий SVG, без відтворення або кадрування логотипу зі стороннього зображення.

## Як працює збереження

Незавершене проходження автоматично записується в `localStorage` після кожної зміни стану. Зберігаються епоха, номер картки, ресурси, приховані риси, прапорці, рішення, випадкові події, кризи й поточна проміжна сцена. Ключ має версію структури (`mashyna-chasu:save:v1`), тому несумісне майбутнє збереження буде безпечно відкинуто. Після завершення проходження незавершене збереження очищається.

## Як додати картку

1. Додайте новий `StoryCard` у `src/data/storyCards.ts` з унікальним послідовним `id`.
2. Заповніть обидві сцени: `2000` і `2026`.
3. Додайте 2–3 вибори з ефектами, реакціями та, за потреби, `flagPatch`.
4. Змініть `TOTAL_STORY_CARDS` у `src/data/config.ts`.
5. Якщо рішення має відгукнутися пізніше, додайте правило у `src/game/deferredEffects.ts`.
6. Оновіть перевірки цілісності даних.

## Як додати випадкову подію

Додайте об’єкт у `src/data/randomEvents.ts`. Поле `era` не дає подіям різних епох змішуватися, а `id` використовується для захисту від повторів у межах одного проходження. Для зміни моментів появи відредагуйте список `[3, 8, 12]` у `scheduleStorySteps` у `src/game/engine.ts`.

## Прийняті рішення для деталей, яких не було в сценарії

- Запізнення у ході 4 та розмова з директором забирають по 1 Енергії, щоб відкладений наслідок був не лише текстовим.
- Якщо Саша отримав частину позики, він повертає саме позичену суму; добрі стосунки означають 6 або більше балів ресурсу «Свої» перед ходом 14.
- Після невдалої другої кризи проходження не обривається: ресурс лишається на нулі, а фінал доброзичливо згадує складний тиждень.
- Для комбінацій двох прихованих рис, яких немає у вихідній таблиці профілів, використовується «Універсальний дослідник».
- У кризі Монет роль фінансового варіанта виконує продаж непотрібного предмета, бо витратити монети при нульовому балансі неможливо.
